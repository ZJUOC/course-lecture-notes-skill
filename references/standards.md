# 讲义标准与写作约定（精简版）

完整版见 ROOT/讲义制作要求与经验.md。

## 目标
- 在已覆盖的范围内能独立自学，理解和做题兼顾。不依赖翻课本：练习要有完整题干、图和提示解析，不写“见教材某题”。
- 重建理解过程：概念为什么引入，关系为什么成立，解题怎样起步，结果怎样检查。不是公式汇总。
- 课堂提供讲解思路和例题；教材补足严谨性和衔接；编者补充推导和纠错。三者的来源分工只记在制作记录里。

## 口吻与结构
- 讲义自己就是授课者，直接讲解。不写“老师说”，不写时间戳或“依据某日课件”。
- 标题学正式教材：概念、关系、方法、应用。例题标题写明对象和所求量。不用悬念式或口号式标题。
- 小节之间靠知识依赖衔接，不用“接下来我们讨论”掩盖缺失的推导。
- 课堂上的口误、不严谨的简化、错误结论：正文只写正确说法；原话、时间戳和改法记在记录的“纠错”一节。课件本身也要核对（例如复变课件把“偏导数存在＋C-R”当成可导的充要条件）。
- 课程管理信息（考核比例、签到等）不写进讲义。

## Markdown 约定（build_lecture.py）
不随主线变化的硬性格式（块标题写法、例题编号、练习单元、概念检查）以 `mainlines.md` 末尾为准，写完用 `format_check.py` 检查。
- 开头：`# 标题`，接着一行加粗的来源说明（课堂：“课程 · 教师课程学习讲义（范围）”；教材：“课程 · 《书名》学习讲义（范围）”），再写导言；`## 学习路线` 用表格。
- 各单元用 `## N 标题 {#英文id}`，小节用 `### N.M`。
- 语义块：
  ```
  ::: {.block .definition}      # definition 绿 / theorem 紫 / result 蓝 / example 棕 / warning 玫瑰
  **定义 3 · 名称**

  内容……
  :::
  ```
- 块内分条写 `(1) …`，每条单独一行；脚本会自动分段（fancy_lists 已关闭，不会被当成列表）。
- 数学用 `$…$`、`$$…$$`，输出 MathML。公式过长时拆成两行 `$$`。
- 图：`![图注，写清图中记号与正文的对应](资源/<课程>原图/xxx.png)`。并排图：`<div class="figure-row">`（三张用 `figure-row three`），内外都要留空行。
- 练习：`### P3 标题 {#practice-p3}`（例题驱动的小节习题用 `#### 习题 k · 名称 {#practice-k}`，挂在小节末尾），题干段落紧跟标题（脚本会装进“练习 · 先独立作答”块），再写 `<details><summary>提示 · …</summary>…</details>` 和 `<details><summary>解析</summary>…</details>`；details 内外都要留空行。最后加 `### C 概念检查 {#practice-concepts}`：判断题加一个“核对”details。

## 视觉
浅色页面，Anthropic Serif/Sans 字体，中文用思源宋体子集（每门课单独一个字体目录，不改其他课程的字体文件）；只做桌面版，不做手机版验收。

## 已知的坑
1. 只读转写文字会漏掉题目；嵌图必须看。DOCX 图片可能是 DrawingML `blip`，也可能是 VML `imagedata`，两种都要抽取。
2. 渐进显示的课件截图，最后一帧未必最好，可能被弹窗遮挡；取最清楚的中间帧。
3. 文件名里的日期可能不对，以转写正文头部的日期为准。
4. OCR 对公式、上标、指数不可靠（例如 e^{πi/2}z 会被识别坏），只能用于检索。
5. 学生上传的作业 PDF 可能是自己的答案，不是题目；老师“发到群里”的作业清单常常没有提供，要在交付时说明。
6. 构建前先备份。Pandoc 的 fancy_lists 已关闭。
7. 数学正确不代表教学完整：核对模型条件（互斥、独立、可微、连通等），不要只核对最终数值。
8. 并排小图要只裁图形，否则文字看不清。
9. 课件算例的算术和修约常有错误；把课程规定的修约规则写成函数，所有数值都用它重算。
10. 课件 PDF 整页截图时，用非白像素的包围盒自动裁掉白边，再缩到 1300 px 宽并量化成 256 色，体积约缩小 75%。
11. 公式里的 `{\rm 中文}` 一旦跨行，Pandoc 就解析失败，页面上直接显示 `$$`，而且不会产生 merror。一律改写为 `\text{}`。desktop_qa 的 rawDollar 必须为 0。
12. 电路题：写一个小的节点电位求解器（支路表：R/I/V），独立求解每道题并做功率平衡；比逐式代入更能发现方向和符号错误。图注里的判断（例如哪些子图是树）要看原图逐个核对。
13. 不用 Haiku 等小模型制作讲义或自绘图。2026-10 发现 Haiku 画的独立性面积图、割集图与正文不符；自绘图要按公式逐项核对，图注写“按公式绘制”。
14. 复积分、电势等积分结论用参数化数值积分复核（中点法或 scipy），不要只核对代数推导。
15. `contact_sheet.py crop` 的 spec 键名不要带扩展名（会生成 `x.png.png`），并会在输出目录写 `裁切清单.json`；用完要并入 `制作记录/构建/<课程>原图裁切清单.json` 并删除；裁切输出目录是 `ROOT/资源/<课程>原图`。
16. 复变的旧 `build_complex.py` 已废弃，统一用 `build_lecture.py`。
17. 自绘图写成脚本（例：讲义项目的 `制作记录/构建/draw_<课程>_vN.py`，输出到 `资源/<课程>原图/`）：按公式算坐标、直接输出 SVG，并对图中每个数值结论做断言、写 json。查看效果：本机无 rsvg/ImageMagick 时，用 Playwright `chromium.launch(channel='chrome')` 截图；标签重叠、曲线越界要逐张看。等值线用 contourpy 求折线，再用 SVG clipPath 裁到区域内。
18. 复现：Skill 必须能从源稿重建出成品。改了构建脚本或阅读器之后，把 ROOT 复制到 scratchpad，`LECTURE_ROOT=<副本> python3 $S/build_all.py`，再与原成品比较：底稿逐字节 `cmp`，页面比较 `<main>` 和 `#concept-data`；不同就要能逐条解释。2026-10-14 的整理就是这样验证的（四门课逐字节相同，物理只差有意改动）。
19. 不要用 `re.sub` / `re.subn` 的替换串插入 JSON 或 TeX：替换串里的反斜杠会被当成转义（`\\bar` 变成退格符 + `ar`）。用函数作替换参数，或改用 BeautifulSoup 插节点。同理，Python 字符串里写 TeX 一律用原始字符串，否则 `\f`、`\b`、`\t` 会变成控制字符（复变正文曾出现 `\x0crac`）。
20. 一致性测试：改了写作规则或脚本后，用同一份输入（例如一本教材的一节）让 3 个互不知情的代理各自从零按 Skill 做讲义，再 `format_check.py a.html b.html c.html` 对照结构画像，并收集它们“不得不自己拿主意”的地方，补进规则。2026-10-14 用赵凯华《光学》§4 做过一次：三份都 PASS、0 警告，例题打头比例都是 100%；差异只在单元数（3 或 4）、补充例题数（7—10）和加粗来源行写法，已在 mainlines.md 里定死。
21. 2026-10-15 用户调整：长公式横向滚动不算问题，不必拆；例题驱动改为“能做出范围内全部教材例题和习题、覆盖全部概念定理证明应用、先例题后理论再附习题”，由覆盖表和 `coverage_check.py` 保证（同日补充：覆盖表只保证不漏，边缘题折叠或一句带过，同型题只记“同类”，讲义不能因此变冗长）；学领域或科研方向时不用例题驱动和题型归纳。
